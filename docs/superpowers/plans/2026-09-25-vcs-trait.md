# Version control trait Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every piece of git knowledge out of the `alacritree` app into an `alacritree_git` crate behind a `VersionControl` trait defined in `alacritree_vcs`, with no change a git user can see.

**Architecture:** `alacritree_vcs` is the integration-type crate: models, `VcsKind`, `VcsError`, the `#[ambassador::delegatable_trait] VersionControl` and `FakeVcs`. `alacritree_git` is the backend crate: `GitBackend` with both transports (git2 natively, batched `sh` in WSL) and its `[integrations.git]` settings. The app dispatches through `enum Vcs { Git(GitBackend) }` in `alacritree/src/vcs.rs`. The trait grows one task at a time, each task moving a slice of git code behind it, so every commit builds and passes. Golden tests captured first prove the wire formats did not move.

**Tech Stack:** Rust 2024 (MSRV 1.85), ambassador 0.5.1, thiserror 2, strum 0.26, git2 0.20 (no default features), schemars 1.2, serde.

**Spec:** `docs/superpowers/specs/2026-09-25-vcs-trait-design.md` (main checkout). Read its "alacritree_vcs", "alacritree_git", "App changes" and "Choosing a backend" sections before starting.

**Scope:** This plan is the refactor, spec order-of-work steps 1 to 10. Two later changes get their own plans. `OpenContextMenu` is one. The other is the backend chooser: the "Version control" section, `ChooseVcs`, `init` and the `state.toml` pin. jj and Mercurial backends are out of scope. So are the trait's `snapshot` and `init` methods and the `vcs_status` request. Each arrives with the first change that calls it: jj's backend for `snapshot`, the chooser for `init`, and the second backend for `vcs_status`.

## Review Focus

1. **A bare repository used as the project root** (`repo.git` with linked worktrees beside it). It must still be discovered as a repository with its worktrees, not as a plain folder. `claims` must not require a `.git` entry. Task 7 pins this.
2. **A WSL project whose distro is stopped or unreachable.** Discovery must stay non-authoritative so the sidebar keeps its last rows, never turning the project into a plain folder. Task 7 pins this through the batch seam.
3. **Deleting a worktree with untracked files.** The dialog must still offer force-delete, now through `VcsError::Unsaved` rather than stderr matching in the app. Task 8b pins this against a real repository.

## Corrections to the spec found while planning

The spec was written against `master`. The stack moved code since, and these points override the spec where they differ.

- `upstream.rs`'s enum is `UpstreamState`, not `Upstream`. It moves to `alacritree_vcs` under its own name.
- The PR remote lookup (`read_remotes`, `push_remote`) now lives in `crates/alacritree_gh/src/lib.rs:297-325`, not `pr_status.rs`. The spec's `push_target` becomes `remotes(&self, checkout, name) -> Remotes { origin_url, push_url }`, because gh needs both URLs. `alacritree_forge::Head` gains `remotes: Option<alacritree_vcs::Remotes>`, filled by the app for native paths. gh's WSL shell lookup stays as it is in this refactor.
- The diff argv builders live in `crates/alacritree_diff_viewer/src/lib.rs` (`diff_args`, `target_git_args`). Only argv building moves behind the trait, as `diff_args(&self, target) -> Vec<String>`. The `-c core.pager` wiring in `launch.rs` stays in the diff viewer crate, because its WSL script resolves the pager inside the distro. The jj plan adds a pager method when it needs one.
- `Probe.head` carries the head label as `Head::label` would spell it, not an opaque token. `LivenessCache::branch_moved` compares it with the discovered checkout's label, which keeps today's external-switch detection exact.
- `claims` is a cheap pre-check that may answer true when unsure. Git's native `claims` is `git2::Repository::open(root).is_ok()`, which matches today for bare repositories. Its WSL `claims` answers true and lets the batch decide.
- `detect` takes no pin in this plan. The pin arrives with the backend chooser.

/// Temp paths differ per run and per OS, so they become `<home>` and forward
/// slashes before comparing.
fn normalize(text: &str, home: &Path) -> String {
    let variants = [
        home.display().to_string(),
        home.display().to_string().replace('\\', "\\\\"),
        home.display().to_string().replace('\\', "/"),
    ];
    let mut out = text.to_string();
    for v in variants.iter().rev() {
        out = out.replace(v.as_str(), "<home>");
    }
    out.replace("\\\\", "/").replace('\\', "/").replace("\r\n", "\n")
}

fn assert_golden(name: &str, actual: &str) {
    let path = PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("tests").join("golden").join(name);
    let committed = std::fs::read_to_string(&path).unwrap_or_default().replace("\r\n", "\n");
    if committed == actual {
        return;
    }
    if std::env::var(UPDATE).as_deref() == Ok("1") {
        std::fs::create_dir_all(path.parent().unwrap()).unwrap();
        std::fs::write(&path, actual).unwrap();
        return;
    }
    let (line, was, now) = committed
        .lines()
        .zip(actual.lines())
        .enumerate()
        .find(|(_, (a, b))| a != b)
        .map_or((0, "", ""), |(i, (a, b))| (i + 1, a, b));
    panic!(
        "{} changed. It pins what git users see and is regenerated only before a refactor, with \
         `{UPDATE}=1`.\n\nfirst difference at line {line}:\n  committed: {was}\n  now:       {now}",
        path.display()
    );
}

fn stdout(out: &Output, home: &Path) -> String {
    assert!(out.status.success(), "stderr: {}", String::from_utf8_lossy(&out.stderr));
    normalize(&String::from_utf8_lossy(&out.stdout), home)
}

//! What every backend reports, in words none of them owns: a checkout is a
//! git worktree, a jj workspace or a Mercurial share.

use std::path::PathBuf;

/// The backends, as `state.toml`, menus and wire fields spell them.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, strum::EnumString, strum::IntoStaticStr, strum::Display, strum::EnumIter)]
#[strum(serialize_all = "lowercase")]
pub enum VcsKind {
    Git,
    Jj,
    Hg,

//! A backend that answers from a script, for tests of code that drives one
//! without a repository on disk.

use std::path::{Path, PathBuf};
use std::sync::{Arc, Mutex};

use crate::{VcsKind, VersionControl};

/// Clones share the recorded requests, so a test keeps one clone and hands
/// the other to the code under test.
#[derive(Debug, Clone)]
pub struct FakeVcs {
    root: PathBuf,
    kind: VcsKind,
    calls: Arc<Mutex<Vec<String>>>,
}

impl FakeVcs {
    pub fn new(root: impl Into<PathBuf>) -> Self {
        Self { root: root.into(), kind: VcsKind::Git, calls: Arc::default() }
    }

    pub fn with_kind(mut self, kind: VcsKind) -> Self {
        self.kind = kind;
        self
    }

    /// Every request, in order, as `method path`.
    pub fn calls(&self) -> Vec<String> {
        self.calls.lock().unwrap_or_else(|e| e.into_inner()).clone()
    }

    fn record(&self, method: &str, path: &Path) {
        self.calls.lock().unwrap_or_else(|e| e.into_inner()).push(format!("{method} {}", path.display()));
    }
}

impl VersionControl for FakeVcs {
    fn claims(&self, root: &Path) -> bool {
        root == self.root
    }

    fn kind(&self) -> VcsKind {
        self.kind
    }
}
